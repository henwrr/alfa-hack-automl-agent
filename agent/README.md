# AutoML-агент (v1)

Запуск как в `baseline.py`:

```bash
OPENAI_API_KEY=... OPENAI_MODEL=... OPENAI_BASE_URL=... python solution.py path/to/task.md
```

Результат — `submission.csv` (путь из `task.md`, по умолчанию рядом с `task.md`) и журнал экспериментов `agent_journal.json`.

## Как устроено

1. `task.py` — разбор `task.md`: пути к CSV, `id`, таргет (из `sample_submission` и разницы train/test), тип задачи, метрика (regex по строкам «Основная метрика…», LLM — только если не нашлось).
2. `data.py` — типы признаков (num / cat / datetime / text), базовый фрейм, DSL безопасных FE-действий (ratio, product, diff, log, row_stats, group_agg, freq, count_nan, drop). Таргет в FE не участвует → нет утечки.
3. Сразу пишется fallback-сабмит (константа / мода), дальше файл только перезаписывается при улучшении.
4. `research.py` — цикл AutoResearch на LightGBM:
   - baseline → эвристики (log1p таргета, веса классов, частоты категорий, агрегаты групп признаков, отношения топ-признаков, параметры);
   - LLM (Qwen) предлагает гипотезы в виде JSON-действий, видит описание задачи, признаки, важности и журнал;
   - гипотеза принимается, если улучшение на фолдах устойчиво (парное сравнение по тем же фолдам, mean > 0.5·SE).
5. Финал: CatBoost + XGBoost + LightGBM с низким lr на лучшем наборе признаков → бленд по OOF → для F1-подобных метрик подбор весов классов (с проверкой на отложенной половине OOF).

## Надёжность

- LLM необязательна: таймауты, ретраи, отключение после 3 сбоев подряд, лимит вызовов.
- Время: мягкий дедлайн = 3 ч − запас; перед каждым экспериментом оценка времени и резерв на финальную фазу.
- Любая ошибка → остаётся последний валидный сабмит.

## Переменные окружения (опционально)

`AGENT_TIME_LIMIT_SEC` (10800), `AGENT_SAFETY_SEC` (900), `AGENT_N_JOBS`, `AGENT_LLM_MAX_CALLS` (30), `AGENT_LLM_TIMEOUT` (180).
