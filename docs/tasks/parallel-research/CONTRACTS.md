# Контракты интеграции

## Семейства (исполнитель families)
Новый automl_agent/families.py. `family_candidates(task, profile, n_jobs=4, limit=3) -> list[dict]`, dict: `{family: str, hypothesis: str, code: str, decision: dict}`. Стабильный порядок, полные self-contained build_model(context), seed/CPU из context. Предпочтительно CatBoost, ExtraTrees и Linear (или HistGradientBoosting по данным); реально разные алгоритмы. CatBoost без скрытого fallback для честного сравнения; legacy baseline остаётся запасным вариантом root. Недоступная CatBoost пропускается. Код AST-valid, train CSV с категориями/NaN/infinity, строковые multiclass labels, сохранение/загрузка. Детерминированные bounded CPU model sizes. Никаких изменений modeling.py/strategy.py/root agent.py. Генератор должен укладываться в память публичных таблиц, у linear аккуратная sparse-compatible стандартизация/кодирование, никакого неограниченного dense onehot.

## Планирование процессов (исполнитель scheduler)
`run_parallel_processes(jobs, *, max_workers=2, research_remaining=None)` — generator `(index, ProcessResult)` по мере завершения, jobs — list[dict] с argv,cwd,timeout,n_jobs,memory_limit_mb,env как у run_process. Максимум 2 worker; сумма n_jobs одновременно <=8; сумма индивидуальных memory_limit_mb <=28000 при заданных лимитах. Код из файла уже записан и AST-проверен root. Coordinator вызывает generator и пишет state сам. По изменяемому callback research_remaining() <=0 отменяются текущие процессы, а queued не стартуют; статус cancelled/time_budget явный (договориться сообщением). KeyboardInterrupt/GeneratorExit/исключение callback: выставить общий cancel_event, остановить worker process groups, дождаться cleanup, пробросить исключение. runtime.run_process получает необязательный cancel_event и проверяет его в loop (prelaunch тоже). Существующие вызовы без него работают. Не возвращать один process twice. Для queued отменённых задач допустим ProcessResult(cancelled, exit None). Функция не пишет journal и не вызывает scorer/publisher.

## Reserve (исполнитель budgeting)
`initial_reserve_seconds(total_seconds) -> float` — 15% без прежнего cap600. `plan_finalization(*, total_seconds, validation_fraction, best=None, train_rows=None) -> dict` поля: reserve_seconds, estimated_fit_seconds, source, selected_trial, row_scale, safety_factor, overhead_seconds. best — ExperimentResult с seconds (полное wall time evaluate subprocess). При измерениях: размер full train / fit train, safety factor >=1.5, небольшой IO запас, floor около5% total; total clamp и честная отметка feasibility если estimate больше total. При отсутствии успешного best начальный reserve15%. Чистая функция, результаты восстанавливаются из durable trial ledger, без часов/скрытого состояния. Root ставит Budget.reserve_seconds из плана, журналирует изменения и сохраняет snapshot. Финальный timeout root считает из оставшегося общего deadline с запасом записи, не trial-timeout.

## Root
CLI: --parallel-trials {1,2} default2; --n-jobs default4 pertrial; --family-trials default3 (1=legacy baseline only), max-trials общий. При слишком малом max-trials для полного comparison + минимум двух LLM попыток сохраняется baseline-only; offline может использовать весь бюджет семейств. Необязательный ExperimentResult.origin ('baseline','family','llm', None legacy). Все deterministic family trials is_baseline=True для совместимого счётчика, origin уточняет фазу. Новое run_experiments(experiments:[{hypothesis,code,decision?}, ...], maxItems2) рядом с прежним run_experiment. Batch handler даёт отдельный status/error на каждого; LLM calls/usage считаются один раз на ответ. Root последовательно создаёт trial_id/intent, затем запускает процессы параллельно, по завершении root оценивает/выбирает/пишет. Tie-break стабильный по trial_id, а не скорости завершения. Новые события family_comparison_started/completed, batch_started/completed, reserve_updated; артефакт family_comparison.json. Recovery не повторяет неизвестные outcomes и учитывает admission code_hash. Аналитика elapsed model fit/start/finish и manifest n_jobs доказывает overlap в validation evidence.
