# MVP универсального ML-агента с AutoResearch harness

## Цель и текущая ситуация

Создать MVP универсального CLI-агента для кейса «AI-агент для разработки ML-моделей». Агент читает описание задачи и данные, сам предлагает и проверяет гипотезы, оценивает модели и сохраняет предсказания. Главный приоритет пользователя — качество harness: управление исследованием, восстановление, проверки и воспроизводимость.

Исходные материалы: PDF кейса, `baseline.py`, неизменённый организаторский `requirements.txt`, каталоги «Регрессия» и «Многоклассовая классификация». Продуктового кода и тестов в исходном Git-коммите нет. Исследования выполняются отдельными агентами GPT-6 Luna xhigh в изолированных worktree.

## Ответы и ограничения

- Подтверждено пользователем 19.10.2026: интерфейс CLI, веб-интерфейс не требуется.
- Срок пользователя: до 26 октября 2026 года. Бюджет одного запуска: до трёх часов.
- Критерии ниже согласованы; численного порога RMSE/Macro F1 пока нет. Улучшать качество при сохранении универсальности.
- API организаторов пока отсутствует. Для локальной валидации разрешена любая модель; доступны Ollama `qwen2.5-coder:7b`, `qwen3.5:9b`, `mistral-nemo:latest`.
- Для платформы: Python 3.12, 8 CPU, 32 GB RAM, без интернета, только разрешённые библиотеки; API и имя модели берутся из переменных окружения baseline. Условия платформы перепроверяются по CASE_SUMMARY.md.
- Локальная машина: macOS arm64, 24 GiB RAM. Для проверки создаётся `.venv` с Python 3.12 и необходимым подмножеством разрешённых зависимостей; инструменты тестирования — отдельно от runtime.
- Результат платформы: ZIP с `solution.py` в корне, запуск по контракту baseline, `submission.csv` в каталоге task.md.
- Оба локальных task.md ссылаются на вложенные пути, хотя CSV лежат рядом с task.md. Требуется общий resolver без привязки к именам двух публичных задач.
- Скрытые задачи неизвестны: нельзя зашивать имена таргетов, публичные схемы и готовые ответы в продуктовый код. Код экспериментов под конкретные данные может генерировать агент во время запуска.
- Все изменения после проверки коммитить локально в `aprelskiy_branch`, сообщения короткие и понятные. Пользователь не просил push или отправку на платформу.
- Дополнительных требований организаторов пользователь не знает.

## Критерии приёмки

| ID | Сценарий / вход | Ожидаемый результат |
|---|---|---|
| AC1 | `python solution.py /path/to/task.md` с OPENAI_API_KEY, OPENAI_MODEL, OPENAI_BASE_URL | Прочитана задача; интерфейс совместим с baseline; подмена провайдера выполняется настройками |
| AC2 | Обе публичные задачи с разными target/type/metric | Один и тот же исходный код обнаруживает входы, строит валидацию и завершает запуск без ручных правок под датасет |
| AC3 | Доступна LLM, выполнено несколько итераций | Есть реальные гипотезы и решения LLM, исполняемый код экспериментов, сравнение по метрике и выбор лучшего результата |
| AC4 | Ошибка LLM/невалидный JSON/исключение или timeout эксперимента | Ошибка протоколируется, рабочий результат сохраняется, бюджет ограничен; исследование восстанавливается либо корректно завершается |
| AC5 | Обучены кандидаты | Оценка выполняется на неизменной собственной валидации без включения validation-target в обучение; более слабый кандидат не заменяет лучший |
| AC6 | Завершение/исчерпание бюджета | Валидный CSV в порядке test: верные колонки/строки/id, конечные значения регрессии или допустимые метки классов |
| AC7 | Артефакты запуска | Сохраняются журнал событий, конфигурация без секретов, гипотезы/код, результаты экспериментов и описание итогового решения |
| AC8 | Возобновление прерванного запуска | Проверяются принадлежность данных/конфигурация; завершённые результаты доступны и не теряются |
| AC9 | Упаковка и запуск распакованного ZIP | В архиве есть solution.py и все runtime-модули, отсутствуют данные/секреты/локальные env; автономный smoke проходит |
| AC10 | Unit/integration проверки и реальные прогоны Ollama | Пройдены тесты важных контрактов, оба публичных сценария и сценарии восстановления; фактические команды/результаты отражены в TESTS.md |

## Вне задачи

Веб-интерфейс, отправка на платформу/лидерборд, push без отдельного запроса, внешние датасеты, предобученные ML-модели, инфраструктура production. Победа на скрытом leaderboard и качество будущей Qwen API до появления доступа не являются проверенными результатами MVP.
