# Журнал исследований (oleg_branch)

Все числа — наша локальная валидация, не скор платформы. Регрессия: RMSE (↓) по временным фолдам
«годы 1–4 → год 5» и «1–3 → 4». Классификация: Macro F1 (↑), stratified holdout 80/20 × 2 seed.

## Что узнали из ветки Апрельского (aprelskiy_branch)

- LLM qwen3.5:9b писала **полный код пайплайна** → большинство опытов падали (lambda в FunctionTransformer,
  `class_weights` с неверным именем параметра, `sample_weight` посчитан, но не передан в `fit`).
  На регрессии 4/4 LLM-опыта упали, на классификации 5 успешных — все хуже стартового CatBoost.
- Гипотезы LLM — только гиперпараметры (GOSS, l2_leaf_reg, learning_rate), без анализа причин ошибок.
- Ollama: нужен нативный `/api/chat` с `think=false` и явным `num_ctx`, иначе контекст режется.
- Лучшее у него: ExtraTrees 45.33 (случайный holdout) и CatBoost 0.565.

## Регрессия (WiDS, site_eui)

| Шаг | RMSE | Вывод |
|---|---|---|
| LightGBM дефолт | 49.12 | |
| + target_encode по ключу здания `floor_area+year_built+facility_type` | 40.50 | **главная находка**: 79% строк test — здания, уже бывшие в train; разброс таргета внутри здания 6.8 против 58.7 по выборке |
| + target_lag (таргет здания в прошлом году) | 38.00 | улучшает оба фолда |
| + log1p таргета (skew 4.8) | 36.85 | |
| CatBoost вместо LightGBM | 36.15 | |
| + частотное кодирование, медленнее lr, XGBoost | **34.54** | полный offline-плейбук |

Отвергнуто / не подтвердилось:
- случайный holdout — test целиком Year_Factor=6, train 1–5; случайная валидация завышает качество;
- удаление самых «сдвинутых» погодных признаков (adversarial AUC = 1.0): 37.5 vs 36.2 — хуже;
- один валидационный фолд: разница вариантов ±2 RMSE на уровне шума (лаг и «без погоды» по отдельности
  помогали, вместе — хуже). Отсюда 2 фолда и среднее.

## Классификация (UNSW-NB15, attack_cat)

| Шаг | Macro F1 | Вывод |
|---|---|---|
| LightGBM дефолт | 0.601 | |
| + target_encode по `sbytes` (найден автоматически: 95% test, purity 0.78) | 0.634 | |
| + sqrt-balanced веса классов | 0.659 | balanced (полные) хуже — 0.616 |
| + частотное кодирование | **0.662** | |

Отвергнуто / не подтвердилось:
- CatBoost: 0.649 и в 13 раз медленнее (316 с);
- TE по нескольким колонкам (dbytes, smean, service×proto): на уровне шума;
- удаление сдвинутых признаков: хуже;
- подбор множителей вероятностей классов под Macro F1: на проверочной половине то +0.02, то −0.003 —
  нестабильно, отложено на финальную стадию;
- EM-оценка долей классов в test (label shift): на искусственном сдвиге +0.007, но на реальном test оценка
  вырождается (доля DoS → 0) из-за неразличимых DoS/Exploits и сдвига признаков — **применять нельзя**.

Шум: Macro F1 между фолдами расходится до 0.04 (редкие классы: Worms — 65 строк на весь train).

## LLM (локально qwen3.5:4b через Ollama; 9b не помещается в 8 ГБ RAM)

- Ответ ~50–100 с, промпт ~8–11 тыс. токенов.
- Без подсказок 4B игнорировала найденный ключ сущности (лучший сигнал) и за 5 минут дошла лишь до 45.6.
- Типовые ошибки: повтор уже проверенных спецификаций (8 из 30), удаление столбца, нужного ключу TE,
  `n_estimators: 500` (обрезает early stopping), несуществующие операции.
- Что сделано: сильные ходы хоста до LLM, блок `host_findings` первым в промпте, хост сам выбирает число
  деревьев, `drop` выполняется после операций с таргетом, повтор LLM заменяется ходом плейбука,
  в каждом раунде LLM — ещё один ход плейбука.
- Вывод: маленькая локальная LLM годится для отладки цикла, но не для качества. Реальную пользу
  нужно мерить на Qwen 27B организаторов.

## Длинные прогоны (1 час на задачу, qwen3.5:4b локально)

Первая пара (20–21 октября):

| | Регрессия (код до тюнинга/ансамбля) | Классификация (с тюнингом и ансамблем) |
|---|---|---|
| Лучшая одиночная | 34.54 — найдена плейбуком на 12-й минуте | 0.6646 — тюнинг LightGBM на 43-й минуте |
| Лучшая от LLM | 36.10 (42 опыта, 0 улучшений) | 0.657 (15 опытов, 0 улучшений) |
| Финал | одна модель | ансамбль из 4 моделей: **0.6681**, лучше на обоих фолдах |

Выводы:
- ~70% времени агент ждал LLM (ответ ~2 мин при свопе 12 ГБ на Mac 8 ГБ, эксперимент ~25 с) →
  сделано: пока LLM думает, хост параллельно гоняет плейбук/тюнинг;
- баг: после разового сбоя LLM при пустом плейбуке агент завершался за 16 мин до конца бюджета → исправлено;
- LLM 3 раза пыталась использовать сам таргет как признак — хост заблокировал (KeyError), утечки нет;
- ранняя остановка на 75–95 деревьях в классификации: фиксированные 200/400/800 деревьев то лучше, то хуже
  по seed — шум, early stopping оставлен;
- offline-плейбук без тюнинга исчерпывался за 2–9 мин → добавлена фаза тюнинга (случайный поиск по
  гиперпараметрам трёх бустингов) и финальный ансамбль (Caruana, принимается только если лучше на каждом фолде).

Вторая пара (версия с тюнингом, ансамблем и параллельной работой хоста, пока LLM думает):

| | v1 | v2 |
|---|---|---|
| Регрессия, лучшая одиночная | 34.54 | **34.04** (тюнинг XGBoost) |
| Регрессия, опытов за час | 42 | ~240 |
| Классификация, лучшая одиночная | 0.6646 | **0.6659** — улучшение дала LLM (exp_020) |
| Классификация, улучшений от LLM | 0 | 4 |

- Ансамбль регрессии (9 моделей) 34.04 → 33.80 в среднем, но на втором фолде чуть хуже (32.34 vs 32.28) —
  старое правило «лучше на каждом фолде» его отклонило. Заменено на честную проверку: отбор на одном фолде,
  оценка на другом; ансамбль принимается, если в среднем выигрывает на невиденных фолдах.
- Ансамбль классификации не отработал из-за бага (передавалась строка вместо списка id) — исправлено.

  с поэтапным урезанием истории/диагностики/описания.

## По вопросам сокомандника (21 октября)

Бейзлайн CatBoost vs LightGBM (оба с early stopping, 2 фолда, дефолтные параметры):

| Задача | LightGBM | CatBoost | CatBoost lr=0.15 |
|---|---|---|---|
| Регрессия (RMSE ↓) | 49.12, 8 с | **46.16**, 12 с | 47.37, 12 с |
| Бинарная синтетика (ROC-AUC ↑) | 0.8196 | **0.8245** | 0.8228 |
| Мультикласс UNSW (Macro F1 ↑) | **0.601**, 26 с | 0.560, 888 с | 0.560, 495 с |

Но в полном цикле (600 с, регрессия) старт с CatBoost дал итог **хуже: 35.38 против 33.85**.
Жадный цикл застревает: после CatBoost+TE (36.20) лаг и log-таргет уже не улучшают модель и не принимаются,
опыты в 2–4 раза медленнее (54 опыта против 68). Старт с быстрого LightGBM отбирает признаки, а CatBoost
пробуется сильным ходом сразу после них (36.85 → 36.15). → бейзлайн оставлен LightGBM
(можно переключить `AGENT_BASELINE=catboost`); early stopping включён для всех бустингов.
Вывод на будущее: жадное «улучшай лучшую модель» чувствительно к стартовой точке — кандидат на улучшение
(например, проверять сильные ходы признаков на быстрой модели независимо от текущего семейства).

Также:
- спецификация эксперимента и ответ LLM — pydantic-схемы (`agent/schemas.py`); ошибки валидации уходят LLM
  понятным текстом; JSON Schema ответа передаётся в structured output (Ollama `format` — по умолчанию,
  OpenAI-совместимый `response_format` — при `AGENT_STRUCTURED=1`); проверено на qwen3.5:4b;
- LLM в 20-минутном прогоне: 3 из 5 ошибок — попытка использовать таргет `site_eui` как признак (хост блокирует),
  1 — несуществующий параметр CatBoost `l1_leaf_reg`;
- `early_stopping_rounds` (20–1000) теперь поле спецификации: LLM может менять терпение, а хост сам
  передаёт его в нужный бустинг (в `params` по-прежнему запрещён, чтобы не было двойной передачи).
