# Журнал исследований (oleg_branch)

Все числа — наша локальная валидация, не скор платформы. Регрессия: RMSE (↓) по временным фолдам
«годы 1–4 → год 5» и «1–3 → 4». Классификация: Macro F1 (↑), stratified holdout 80/20 × 2 seed.

## Что узнали из ветки Апрельского (aprelskiy_branch)

- LLM qwen3.5:9b писала **полный код пайплайна** → большинство опытов падали (lambda в FunctionTransformer,
  `class_weights` с неверным именем параметра, `sample_weight` посчитан, но не передан в `fit`).
  На регрессии 4/4 LLM-опыта упали, на классификации 5 успешных — все хуже стартового CatBoost.
- Гипотезы LLM — только гиперпараметры (GOSS, l2_leaf_reg, learning_rate), без анализа причин ошибок.
- Ollama: нужен нативный `/api/chat` с `think=false` и явным `num_ctx`, иначе контекст режется.
- Лучшее у него: ExtraTrees 45.33 (случайный holdout) и CatBoost 0.565.

## Регрессия (WiDS, site_eui)

| Шаг | RMSE | Вывод |
|---|---|---|
| LightGBM дефолт | 49.12 | |
| + target_encode по ключу здания `floor_area+year_built+facility_type` | 40.50 | **главная находка**: 79% строк test — здания, уже бывшие в train; разброс таргета внутри здания 6.8 против 58.7 по выборке |
| + target_lag (таргет здания в прошлом году) | 38.00 | улучшает оба фолда |

| CatBoost вместо LightGBM | 36.15 | |
| + частотное кодирование, медленнее lr, XGBoost | **34.54** | полный offline-плейбук |

Отвергнуто / не подтвердилось:
- случайный holdout — test целиком Year_Factor=6, train 1–5; случайная валидация завышает качество;
- удаление самых «сдвинутых» погодных признаков (adversarial AUC = 1.0): 37.5 vs 36.2 — хуже;
- один валидационный фолд: разница вариантов ±2 RMSE на уровне шума (лаг и «без погоды» по отдельности
  помогали, вместе — хуже). Отсюда 2 фолда и среднее.

## Классификация (UNSW-NB15, attack_cat)

| Шаг | Macro F1 | Вывод |
|---|---|---|
| LightGBM дефолт | 0.601 | |
| + target_encode по `sbytes` (найден автоматически: 95% test, purity 0.78) | 0.634 | |
| + sqrt-balanced веса классов | 0.659 | balanced (полные) хуже — 0.616 |
| + частотное кодирование | **0.662** | |

Отвергнуто / не подтвердилось:
- CatBoost: 0.649 и в 13 раз медленнее (316 с);
- TE по нескольким колонкам (dbytes, smean, service×proto): на уровне шума;
- удаление сдвинутых признаков: хуже;
- подбор множителей вероятностей классов под Macro F1: на проверочной половине то +0.02, то −0.003 —
  нестабильно, отложено на финальную стадию;
- EM-оценка долей классов в test (label shift): на искусственном сдвиге +0.007, но на реальном test оценка
  вырождается (доля DoS → 0) из-за неразличимых DoS/Exploits и сдвига признаков — **применять нельзя**.

Шум: Macro F1 между фолдами расходится до 0.04 (редкие классы: Worms — 65 строк на весь train).

## LLM (локально qwen3.5:4b через Ollama; 9b не помещается в 8 ГБ RAM)

- Ответ ~50–100 с, промпт ~8–11 тыс. токенов.
- Без подсказок 4B игнорировала найденный ключ сущности (лучший сигнал) и за 5 минут дошла лишь до 45.6.
- Типовые ошибки: повтор уже проверенных спецификаций (8 из 30), удаление столбца, нужного ключу TE,
  `n_estimators: 500` (обрезает early stopping), несуществующие операции.
- Что сделано: сильные ходы хоста до LLM, блок `host_findings` первым в промпте, хост сам выбирает число
  деревьев, `drop` выполняется после операций с таргетом, повтор LLM заменяется ходом плейбука,
  в каждом раунде LLM — ещё один ход плейбука.
- Вывод: маленькая локальная LLM годится для отладки цикла, но не для качества. Реальную пользу
  нужно мерить на Qwen 27B организаторов.
